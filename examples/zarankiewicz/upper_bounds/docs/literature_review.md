## 1. Problem statement and notation

**The Zarankiewicz function.** For positive integers `m, n, s, t`, `z(m,n;s,t)` is the maximum number of ones in an `m × n` 0/1 matrix that contains no all-ones `s × t` submatrix, where the `s` indices are rows and the `t` indices are columns. Equivalently, it is the maximum number of edges in a bipartite graph with parts of sizes `m` and `n` that contains no `K_{s,t}` with the `s`-side in the part of size `m`. Guy's `k_{s,t}(m,n) = z(m,n;s,t) + 1` is the least number of ones that forces the submatrix; OEIS A001197, A001198 and A006613 store `k`, not `z` [zarankiewicz_theory_counting]. Throughout this thesis `s = t = 3` unless stated, and `z(m,n)` abbreviates `z(m,n;3,3)`; several sources write `Z(m,n,3,3)` [dfield26] [afrasyab26] or `z(m,n;3)` [hou26] [collins16] for the same number.

**Matrix convention.** A matrix is `A : Mat m n := Fin m → Fin n → Bool` (this is the ZarPrune definition, `lean/ZarPrune/Basic.lean`). Row sums `r_i`, column sums `c_j`, weight `w = Σ r_i = Σ c_j`. The forbidden pattern is stated with *strictly increasing* index tuples: `HasKst P A := ∃ R : Fin s → Fin m, ∃ C : Fin t → Fin n, Incr R ∧ Incr C ∧ ∀ a b, A (R a) (C b) = true`. This is the same predicate as "some `s` rows and `t` columns meet in an all-ones block" and, for `s = 3`, the same as the codegree form used by every evolved lower-bound program ("no three rows share three columns") [bhan2026_lower_bounds] [padhi2026_gpu]; the bridge lemma between the two forms is elementary but not yet written (§3.5, P-codeg).

**Symmetries.** `z(m,n;s,t) = z(n,m;t,s)` (transpose), and a `K_{s,t}`-free matrix need not be `K_{t,s}`-free when `s ≠ t` [zarankiewicz_theory_counting]. Row and column permutations preserve both `HasKst` and `weight`, so `Valid P A := ¬HasKst P A ∧ P.w ≤ weight A` is invariant under `S_m × S_n`. Deleting a one preserves `K_{s,t}`-freeness, so "some matrix with `≥ w` ones" and "some matrix with exactly `w` ones" are equivalent for existence [afrasyab26 L10] [dfield26 §3.1]; every case analysis in the literature works at exactly the first excluded weight `w = z + 1`.

**Hypergraph view.** Rows are vertices, columns are edges (a multiset of subsets of `[m]`, sizes `c_j`); `K_{s,t}`-free means every `s`-set of vertices lies in at most `t − 1` edges, which Davies–Gill–Horsley call `(s, t−1)`-linear [dgh26]. This view is what makes the counting bounds of §3–4 linear programs in the column-size distribution `n_i = #{j : c_j = i}`.

**What a "case" is.** Tan's decomposition fixes an unordered row-sum partition and an unordered column-sum partition of `w` and solves one SAT instance per pair [tan2022]. ZarPrune's `Profile m n := (row : Fin m → Nat) × (col : Fin n → Nat)` is the ordered refinement; a prune on profiles restricts to a prune on partitions, but the closure theorem (`upper_bound_of_cover`) must then absorb the permutation symmetry on its `cover` side (§6.4). dfield's decomposition fixes only the column-degree histogram [dfield26]. Both granularities appear below.

**The two halves of an upper-bound proof.** In every computational upper-bound proof surveyed, the argument has the shape "enumerate cases; kill some by an arithmetic argument; refute the rest by a solver or certificate". ZarPrune's closure theorem states this shape exactly:

```
upper_bound_of_cover (p : Prune P) (survivors : List (Profile P.m P.n))
  (cover   : ∀ A, Valid P A → p.kill (profileOf A) = true ∨ profileOf A ∈ survivors)
  (refuted : ∀ q ∈ survivors, ∀ A, profileOf A = q → ¬ Valid P A) :
  ∀ A, ¬ HasKst P A → weight A < P.w
```

The literature review below is organised around its three obligations: the `Prune` term (§3–4: which arithmetic arguments exist, and which are provable), `refuted` (§6: certificates), and `cover` (§6.4: enumeration completeness and symmetry).

## 3. The SAT case-split method (Tan 2022) and the pruning-lemma catalogue

### 3.1 The method

Tan computes `z_{a,b}(m,n)` for `a = b ∈ {2,3,4}` by SAT solving [tan2022]. The base encoding is one Boolean variable per cell (cell `(i,j)` is DIMACS variable `i·n + j + 1`, row-major), one clause `⋁ ¬a_{ij}` per `a × b` minor (`C(m,a)·C(n,b)` clauses; 313,600 at `z_3(16,16)`), and a cardinality constraint requiring *exactly* `w` ones. Any solution proves `z ≥ w`; UNSAT proves `z < w`. The instance is never solved whole:

> "An admissible or maximal matrix clearly remains as such under all row and column permutations. It is therefore enough for a given w to solve instances where the row and column sums are fixed, over all possible combinations of unordered row and column partitions not forbidden by the arguments of section 2 – an approach very much like Heule's cube-and-conquer paradigm." [tan2022 §3.1, quoted in tan2022_sat §4.2]

So the cubes are (unordered column partition, unordered row partition) pairs of `w`. Per surviving pair the CNF adds Sinz sequential-counter equality constraints on every row and column (`k(N−k)` auxiliaries per line, four clause families; brute-force verified correct for `N ≤ 5` **[reproduced]** [tan_kyoto_repo §5]) and lexicographic order within runs of equal-sum rows/columns (`N−1` auxiliaries per comparator, "1 before 0"), justified by Theorem 3.2 (alternate row/column lex sorting terminates, via the potential `f(A) = Σ 2^{i+j} a_{ij}`; the partition clause "rows and columns cannot move across partitions" is stated explicitly) [tan2022_sat §4.4]. Kissat is run with only `--sat`/`--unsat` on one laptop; `any exit code other than 10 is treated as UNSAT` and DRAT proofs, though requested, are never checked [tan_kyoto_repo §6]. Isomorph rejection uses nauty `shortg`; automorphism groups GAP; one model count used sharpSAT.

**Algorithm 1 (column-partition generator), transcribed from the paper with the code's corrections** [tan2022_sat §4.2]:

```
 1: p ← empty stack
 2: procedure P(a, b, m, n, w)
 3:   L_A ← (b−1)·C(m, a)                          ▷ set once from the ORIGINAL m
 4:   if Σ_i C(p_i, a) > L_A  or  Σ p > z_{a,b}(m, |p|) then   ▷ |p| = current length; z = best PROVED bound
 5:     return
 6:   else if w = 0 then
 7:     output p                                    ▷ trailing zero parts implicit
 8:   else if w > (m−1)·n then                      ▷ paper prints k for w
 9:     d ← w − (m−1)·n
10:     push m d times; P(a, b, n−d, w−dm); pop d times
13:   else
14:     for t ∈ [⌈w/n⌉, min(w, m)] do
15:       push t; P(a, b, t, n−1, w−t); pop            ▷ t becomes the new upper limit ⇒ non-increasing parts
18:     end for
19:   end if
```

Theorem 3.1 (v2 addition): the algorithm outputs all partitions of `w` into `n` parts in `[0, m]`, non-increasing, in lexicographic order, pruned at every prefix by Arguments A and I; the prefix is sound because for non-increasing parts "the first `n'` column sums in `p` ... are the most pessimal partition choice for the column sums of an `m × n'` minor" [tan2022_sat §4.2]. In the code (`utilities.get_partitions`) the Argument-I limits are `Elims = {j : zbounds(a,b,m0,j)[1] for j in range(b, n0)}` with `zbounds = min(Roman, Roman-transposed, every "< k" record already in data/)`, i.e. **the generator is recursive in the campaign's own SAT-proved results** [tan_kyoto_repo §3]. Row partitions are generated with the roles swapped. Pairs are then filtered by Argument D in its pessimal profile form (§3.3, P2), and when `a = b, m = n` only unordered `{cpart, rpart}` pairs are kept (a transposition symmetry reduction, not a prune) [tan_kyoto_repo §4].

**Second-level cubes exist in Tan's own work:** for `z_2(23)=115` the single surviving pair had `6^6` models even with lex constraints; Tan split on the sums of a `4×4` grid of `4×4` boxes with a hand symmetry argument (12 cases), and `extend_solution`/`set_cubes` implement partial-assignment cubes [tan_kyoto_repo §9]. The talk names "enumerating all possible ways to assign the first two rows and columns" as future work.

### 3.2 Notation for the catalogue

`P = ⟨m, n, s, t, w⟩`, `A : Mat m n`, hypothesis `hfree : ¬HasKst P A` unless stated, `c_j = colSum A j`, `r_i = rowSum A i`, binomials `C(x,k) = 0` for `x < k`. A **profile prune** is a computable `kill : Profile m n → Bool` with `sound`. A **conditional prune** additionally assumes a proved bound for a smaller cell (a `tbl` hypothesis). An **addition** (ADD) is a symmetry reduction that is *not* a prune and must live in `cover` or in the certificate (§6.4). Lean notes refer to the project's actual configuration: the trusted core (`Sum/Basic/Prune/Prunes.lean`) is Mathlib-free on Lean 4.34.0; after E5 the project decided to add a Mathlib-backed `ZarPrune/Counting.lean` (targeted imports `Finset`, `BigOperators`, `Nat.Choose`, `Powerset`; 1.8 s per check vs 0.3–0.5 s Mathlib-free) because LLMs know that API and a hand-rolled subset-counting layer "would make every evolved proof harder for no soundness gain" [experiments/LOG.md E5]; the E8 workflow has produced attempt files `lean/Attempts/{A1..A3,D1..D3,E1,E2}.lean` with `colBudget`, `rowBudget`, `rowLocalBudget`, `hasKst_transpose`, `killDthr_sound`, `killDsum_sound` and `Prune` packagings, not yet integrated at the time of writing. Each catalogue entry therefore gives both the Mathlib route and the Mathlib-free cost estimated by the readers.

### 3.3 The catalogue

**P0 — sanity prunes (proved, Mathlib-free).** `deficit` (`Σ r_i < w`), `mismatch` (`Σ r_i ≠ Σ c_j`, via `sumFin_swap`), `rowCap`/`colCap` (`r_i > n`, `c_j > m`), folded into `baseline` by `Prune.or`; axioms `{propext, Quot.sound}` [lean/README.md]. Padhi's "feasibility" rule (ii) is this lemma [padhi2026_gpu L2].

**P1 — Argument A / Kővári–Sós–Turán / Roman capacity (both orientations).** Statement: `Σ_j C(c_j, s) ≤ (t−1)·C(m, s)` and `Σ_i C(r_i, t) ≤ (s−1)·C(n, t)`. Hypotheses: `hfree` only; `s ≤ m`, `t ≤ n` (else vacuous); the inequality holds for arbitrary profiles with `C(a,b) = 0` for `a < b`, so no "columns ≥ s−1" normalisation is needed [dgh2024_lp_bounds §8.3]. Proof: double count pairs (increasing `s`-tuple of rows, column all-ones on it); each tuple lies in `≤ t−1` columns or `HasKst`; column `j` contains `C(c_j, s)` tuples. Kill: `decide ((t−1)·C(m,s) < Σ_j C(pf.col j, s))` or the row analogue. Sources: Tan Argument A (verbatim in [tan2022_sat §3]); Collins Lemma 2 right inequality [hou2026_13x18 L4]; DGH constraint (3); dfield `sum_choose_columnDegree_le` (Mathlib, Lean 4.29) [dfield26 §5.2]; Afrasyab eq. (4) [afrasyab26 L1]; Padhi prints it mis-indexed [padhi2026_gpu §2.2]. On a fixed profile P1 **dominates every convexity-derived global bound** (KST, Reiman, Znám, Roman for every `p`): those are `Σ C(c_j,s) ≥ linear` lower bounds, so if the linear bound exceeds the budget so does the exact sum [zarankiewicz_theory_counting P1]. It is the workhorse: at `w = Roman` it kills all but a handful of partitions; it removes far-from-regular profiles but leaves extremal witnesses untouched (witnesses use 77–85 % of the column budget, 60–69 % of the row budget) [saurabh2026_five_lb §6]. Lean: with Mathlib, `Finset.card_powersetCard` + `Finset.sum_comm` + `orderEmbOfFin` to build `Incr` tuples, ≈ 50 lines (COUNTING_SPEC; `colBudget` in `Attempts/D1.lean`); Mathlib-free, a hand-rolled `choose`, an enumerator of increasing tuples with `length = choose`, per-column count identity by induction, a tuple-indexed Fubini, and an extraction lemma, 300–600 lines [tan2022_sat L-A] [zarankiewicz_theory_counting P1]. For `s = 2` it collapses to `Σ c_j(c_j−1) ≤ (t−1)m(m−1)`, an algebraic identity plus Fubini [tan_kyoto_repo L1].

**P2 — Argument D (row-local counting) and its pessimal profile test.** Matrix statement (Tan, verbatim): for any row whose ones lie in columns with sums `c_1..c_r`, `Σ_{i=1}^{r} C(c_i − 1, a−1) ≤ (b−1)·C(m−1, a−1)`; transposed form likewise. Proof: delete the row; the `(m−1) × r` submatrix on its columns has sums `c_j − 1` and is `K_{s−1,t}`-free (else the row extends the block), then P1. Profile kill (Tan): with `r_max = max_i r_i` and the `r_max` *smallest* values of `C(c_j − 1, s−1)`, kill if their sum exceeds `(t−1)·C(m−1, s−1)`; both orientations. Kyoto: `sum(comb(c-1,a-1) for c in cpart[-rpart[0]:]) > (b-1)*comb(len(rpart)-1,a-1)` [tan_kyoto_repo §4]. Justification of the max row: the LHS has `r` non-negative terms, monotone in `r`; summing D over *all* rows with true incidences gives `a ×` Argument A, so D-on-the-max-row is genuine extra information [tan2022_sat §4.2]. It is DGH's local inequality (5) with `v = 1` used pointwise [dgh2024_lp_bounds §4]. Power: kills 30–70 % of pairs surviving A/I (`z(16,16;3,3)`, `w=129`: 277,729 → 89,764; `z(13,18;3,3)`, `w=117`: 107,502 → 67,795; `z(15,17;3,3)`, `w=132`: 23,632 → 4,312) [zarankiewicz_theory_counting §5.2] [dgh2024_lp_bounds §8.5]; ~half the cases in the project's E2 tables. Lean: P1 for `(s−1, t)` on a submatrix (delete row `i` via `Fin.succAbove`, restrict to the row's support, transport `HasKst` back by composing increasing maps) plus a rearrangement lemma "sum over any `r` columns ≥ sum of the `r` smallest"; the sorting lemma is the fiddly part Mathlib-free. **Sort-free weaker form** (avoids sorting entirely): for any threshold `θ`, with `N_θ = #{j : C(c_j−1,s−1) ≤ θ}`, kill if `(θ+1)·(r_max − N_θ) > (t−1)·C(m−1,s−1)` [zarankiewicz_theory_counting P2]; this is `killDthr` in `Attempts/D1.lean`, with `killDsum` the sorted version via a layer-cake lemma.

**P3 — D_v (v-subset local counting) and the pair cut.** For every `v`-set `X` of rows, `0 ≤ v ≤ s−1`: `Σ_{j ⊇ X} C(c_j − v, s−v) ≤ (t−1)·C(m−v, s−v)`; `v = 0` is P1, `v = 1` is P2, `v = s−1` is the linear pair cut `Σ_{j ⊇ X} (c_j − s + 1) ≤ (t−1)(m−s+1)` (for `s = 3`: any two rows, `Σ_{common j}(c_j−2) ≤ 2(m−2)`, which is Afrasyab's eq. (9)/(14) and dfield's pair-deficit identity) [zarankiewicz_theory_counting P2] [afrasyab26 L5] [dfield26 P6]. For `v ≥ 2` the common neighbourhood of `X` is not determined by the profile, so D_v is a SAT-side cutting plane (the `pair_cuts` of `encodings_zar.py`), not a profile prune, unless the case index is enriched with codegree information (§10). Aggregated over all `X` it is redundant with P1 (codegree identity `Σ_X deg(X) = Σ_j C(c_j, v)`) [zarankiewicz_theory_counting P10].

**P4 — Argument I / Guy's E (inclusion of minors; conditional).** Matrix statement (Tan, verbatim): for `m' ≤ m`, `n' ≤ n`, every `m' × n'` minor of a witness is admissible and has `≤ z_{a,b}(m',n')` ones. Profile forms: (1) row-prefix / column-prefix: the `k` heaviest rows satisfy `Σ_{top k} r_i ≤ Z(k,n)`, the `k` heaviest columns `Σ_{top k} c_j ≤ Z(m,k)` (Tan's `Elims`, applied to all `b ≤ k < n`); (2) mixed minor: `Σ_{top k} r_i − Σ_{ℓ lightest} c_j ≤ Z(k, n−ℓ)`. Hypotheses: a proved upper bound `Z(m',n') ≥ z(m',n';s,t)` for the cited minor — Roman/Čulík give closed-form seeds, the campaign's own closures give exact ones. Lean: restriction along an increasing `e : Fin n' → Fin n`, `HasKst (A∘e) → HasKst A` by composing `Incr`, `weight (A ∘ e) = Σ_k c_{e k}`, and a selection lemma; medium (150–250 lines Mathlib-free) *but* the prune is a **combinator taking a proof term for the smaller cell**; the harness must maintain a DAG of proved cells exactly as Kyoto's `zbounds` reads `data/` [tan2022_sat L-I] [tan_kyoto_repo §8]. Suggested type: `CondPrune P tbl` whose `sound` may assume `∀ m' n' (B : Mat m' n'), ¬HasKst → weight B ≤ tbl m' n'`, discharged at closure time [zarankiewicz_theory_counting P3]. The project already found and fixed the circularity hazard here: Argument I must be applied to *proper* minors only, otherwise the target cell's own table value bounds itself (E1).

**P5 — Deletion / density (Guy's point C; Collins Lemma 3–4; Afrasyab Lemma 2.1; dfield P3/P4; conditional).** Statement: for every column `j`, `weight A − c_j ≤ Z(m, n−1)`, hence kill if `∃ j, Σ_i r_i − c_j > U` for a proved `U ≥ z(m,n−1)`; equivalently, with total `w`, every column has `c_j ≥ w − U`; row dual with `Z(m−1,n)`; multi-column form `w − (sum of the k smallest c_j) ≤ Z(m, n−k)`; global closed form `Z(m,n) ≤ ⌊n·Z(m,n−1)/(n−1)⌋` [afrasyab26 L3] [hou2026_13x18 L1–L2] [dfield26 P3]. Regularity forcing: if `n·(w−U) > w` the cell dies with no SAT (`(13,18,117)`: `18·7 > 117`); if `0 ≤ w − n·c ≤ n−1` the column multiset is pinned to `{(c+1)^{w−nc}, c^{n−(w−nc)}}` (`(12,18,109) ⇒ {7, 6^17}`) [hou2026_13x18 L2]. Power when the neighbour is tight: 99.99 % of row partitions killed at `(12,18,109)` vs 96 % for KST; 9 of dfield's 12 arithmetic kills at `(10,23,113)` are deletions [hou2026_13x18 §7.2] [dfield26 §8.2]. It is P4 form (1) with `k = m−1`/`n−1`, but deserves its own entry because it is the mechanism by which a closed cell strengthens its neighbours. Lean: `Fin.succAbove` embedding, `sumFin n f = f j + sumFin (n−1) (f ∘ skip j)` (not yet in `Sum.lean`), `HasKst` transport; medium, ≈150 lines; dfield has `deleteRow/deleteColumn`, `UpperBound.addRow_of_average` in Mathlib [dfield26 §5.2]; `Attempts/E1,E2.lean` are the project's versions. A cautionary case: Afrasyab's *two-row* deletion (`e − d_i − d_j + c_ij`) was used in withdrawn certificates that claimed `Z(15,17)=125` and `Z(16,17)=130`, refuted by explicit witnesses [afrasyab26 L11].

**P6 — Edge-local, max-row split and minimum row-degree cut (conditional variants).** Edge-local (DDR Lemma 6): for every one at `(i,j)`, `w − r_i − c_j + 1 ≤ Z(m−1, n−1)`, profile form: for every row `i`, `#{j : c_j ≥ w − Z(m−1,n−1) + 1 − r_i} ≥ r_i`. Max-row split (DHS Prop 3.20, `α = 1`): `w ≤ r_max + Z_{s−1,t}(m−1, r_max) + Z_{s,t}(m−1, n − r_max)`; needs a table for the `(s−1,t)` problem as well. Minimum row-degree cut (dfield P4): every row has `r_i ≥ w − Z(m−1,n)` (10 at `(10,23,113)`), used by dfield as a CNF clause but equally a profile prune [zarankiewicz_theory_counting P3.4–3.5] [dfield26 P4]. Lean: same skeleton as P5; the max-row split additionally needs "inserting the deleted row into an increasing `(s−1)`-tuple", medium-hard.

**P7 — Roman's bound (global; not a new profile prune).** For every integer `p ≥ s−1`: `z(m,n;s,t) ≤ ⌊(t−1)·C(m,s)/C(p,s−1) + n·(p+1)(s−1)/s⌋`, equality iff all column sums are in `{p, p+1}` and every `s`-set of rows has exactly `t−1` common columns [tan2022_sat Thm 2.2] [dgh26 Thm 1.1] [zarankiewicz_theory_counting P4]; Tan makes Guy's exact region precise via the packing number `T_{s,t}(m)` (equality with `p = s` or `s−1` when `(t−1)·C(m,s) − s·T_{s,t}(m) ≤ n`; `T_{3,3}` values from Gurobi; Theorem 2.3 bound on `T`); recomputed packing thresholds for `a=b=3`, `m = 3..16`: `0,2,5,11,23,28,46,60,88,114,143,182,233,280`, reproducing Table 3's solid staircase **[reproduced]** [tan2022_sat §3]. Underlying integer inequality `C(x,s) ≥ C(p,s) + (x−p)·C(p,s−1)` (verified numerically `s ≤ 5, p ≤ 14, x ≤ 24` **[reproduced]**). Roman is dominated by P1 on any fixed profile; its roles are: the starting `w`, the default entries of the minor table for P4/P5, and the explanation of why survivors are near-regular. Lean: P1 + an easy induction; not needed for the gate [tan2022_sat L-Roman].

**P8 — Davies–Gill–Horsley constraint (4), `v = s−1` (a genuinely new profile prune).** With `D = k−s+1`, `R = (t−1)(m−s+1)`, `α = R mod D`, `c = (R−α)/D`, for `s ≤ k ≤ m`, integer-safe form: `Σ_{j: c_j<k} (c_j−s+1)·C(c_j,s−1) + (D−α)·Σ_{j: c_j≥k} C(c_j,s−1) ≤ (D−α)·c·C(m,s−1) + α·Σ_{j: c_j<k} C(c_j,s−1)`; row dual with `(t,s,n,m)` [dgh2024_lp_bounds L1]. Proof (DGH Lemma 3.2): for each `(s−1)`-set `X`, `Σ_{j ⊇ X} (c_j − s + 1) ≤ (t−1)(m−s+1)` (D_{s−1}), then the deficiency rewrite and the integrality/rounding step `deg(X) ≤ c + τ(X)/(D−α)` (the leftover `α < D` cannot be spent on a fraction of an edge), aggregated over all `X` [dgh2024_lp_bounds §4]. Power **[reproduced]**: closes `z(13,17;3,3) ≤ 116` and `z(13,18;3,3) ≤ 121` with zero SAT calls; kills 4–7 % of pairs Tan keeps on frontier cases; at `z(15,17;3,3)`, `w=132`: 38 column partitions pass P1, 14 pass P1+P8 [zarankiewicz_theory_counting §5.2] [dgh2024_lp_bounds §8.4]. Caveat: negative coefficients for sizes with `C(i−v,s−v) < α`, so it is **not safe as a prefix test** in Algorithm 1's order; evaluate on complete partitions [dgh2024_lp_bounds §9]. Lean: P1's layer + per-`X` count + rounding (`Nat.div_add_mod`, `omega`) + aggregation; ≈1.5× P1; "hard but no worse than P2 once P1 exists" [zarankiewicz_theory_counting P5].

**P9 — DGH constraint (4), general `v`.** Same with `C(c_j − v, s−v)`; needed only for the 17 starred cells where `E* ≠ E` (none in `(3,3)`, `m ≤ 16`) [dgh2024_lp_bounds §7]; ≈2× P1.

**P10 — DGH per-set rounding, `v = 1` pointwise (strengthens P2 when `α > 0`).** `(D−α)·r_i ≤ (D−α)·c + τ_i` with `τ_i = Σ_{j ∈ N(i), c_j < k} (D − C(c_j−1,s−1))`; profile-checkable pessimistically like P2 [dgh2024_lp_bounds L5] [zarankiewicz_theory_counting P9]. Gain likely marginal; low priority.

**P11 — Farkas / cutting-planes combination (instance- or profile-level).** Given already-proved linear inequalities `L_k(r,c) ≤ R_k` (instances of P0–P10) and nonnegative integer multipliers `y_k`, kill if `Σ y_k L_k > Σ y_k R_k` on the profile. This is how an LP infeasibility becomes a `Prune P` term without any LP solver in the trusted base: multipliers are found outside (exact rational LP, SCIP-exact/VIPR as dfield does) and only checked inside; `sound` is `omega`-level arithmetic after instantiating the base lemmas [sat_hardness_estimation PL4] [dgh2024_lp_bounds L3]. Example: `E(15,17;3,3) = 6637/50` with three rational multipliers (equality at sizes 7, 8, 9) refutes `w = 133` for the whole cell **[reproduced]** [dgh2024_lp_bounds §8.6]. Afrasyab's per-profile block-polytope LP (variables over all `2^m` supports, constraints (7)–(10), Lemma 5.1) is the same idea at a finer granularity, but its soundness proof needs the map from a matrix to its support-multiplicity vector and rational linear algebra over `~2^13`-length vectors — hard Mathlib-free, plausible with Mathlib and a reflective checker [afrasyab26 L6].

**P12 — Gale–Ryser necessity (K_{s,t}-blind).** For every set `S` of columns, `Σ_{j∈S} c_j ≤ Σ_i min(r_i, |S|)`; checking prefixes of the sorted column sums is the full Gale–Ryser condition (necessary and sufficient for *some* 0/1 matrix) [zarankiewicz_theory_counting P6] [saurabh2026_five_lb P4] [sat_hardness_estimation PL1]. Never fired on 20 tested frontier case sets (survivors are near-regular) **[reproduced]**; cheap insurance certifying the pairing layer. Lean: easy–medium (masked sums + Fubini, ≈100 lines, no `choose`).

**P13 — Dense-row cap (Bonferroni / Balbuena Remark 3.1).** `Σ_{s heaviest} r_i ≤ (s−1)·n + t − 1` and the column dual (= P4 with Čulík's `z(s,n;s,t) = (s−1)n + t − 1`) [zarankiewicz_theory_counting P7]. Fires only in the dense regime; never on frontier cases **[reproduced]**. Include for generality of the library, not for kills.

**P14 — Marked-row deficit residues (dfield P5; Afrasyab §6).** For `s = t = 3`, define `D_r := Σ_{T ∋ r} (2 − λ_T) ≥ 0` where `λ_T` is the number of columns containing the row triple `T`. Identities: `D_r = 2·C(m−1,2) − Σ_{j : r ∈ E_j} C(c_j − 1, 2)` and `Σ_r D_r = 3s` with `s = 2C(m,3) − Σ_j C(c_j,3)` the triple slack. Congruences: if all non-exceptional degrees `d` have `C(d−1,2) ≡ 0 (mod g)`, then `D_r ≡ 2·C(m−1,2) − (exceptional contributions through r) (mod g)` and `D_r ≥` its least non-negative residue; minimising `Σ_r residue` over how rows meet the exceptional columns gives a lower bound on `3s`; kill if it exceeds `3s`. Kills all three `(9,23,104)` profiles (`18/15/12 > 12/3/0` with `g = 3`), all three `(13,23,145)` profiles (`g = 5`), two of the `(10,23,113)` profiles [dfield26 P5]; Afrasyab's Proposition 6.1 (`6^18 7^3 9^1` at `13×22@138`) is a human-readable instance [afrasyab26 §4.4]. It is strictly stronger than LP-strength degree constraints: at `(9,23,104)` the DGH LP has optimum `314/3` and cannot kill any of the three profiles [dfield26 P11]. General `(s,t)` form **[inference]**: weights `C(d−1, s−1)` with capacity `(t−1)·C(m−1, s−1)`. As a profile prune it is a finite enumeration of `2^k` row-membership patterns over `k` exceptional columns (dfield `filters.py::profile_ok` relaxed bitset version; `tier2.py` exact version) [dfield26 P9–P10]. Lean: dfield proves `rowDeficit_add_sum_choose`, `sum_rowDeficit`, `markedTripleCount_eq` in ≈450 Mathlib lines (Counting.lean) and closes cases by `Nat.ModEq` + `omega` after `rcases` on bounded exceptional counts; the residue enumeration itself is Python at `(10,23)` [dfield26 §5]. The evolvable content is the choice of marked rows, exceptional columns and modulus `g`.

**P15 — Pair-deficit residues (dfield P6).** For a row pair `Q`: `D_Q := Σ_{T ⊇ Q} (2 − λ_T) = 2(m−2) − Σ_{j : Q ⊆ E_j} (c_j − 2) ≥ 0`, `Σ_Q D_Q = 3s`, count consistency `Σ_Q #(degree-d columns through Q) = n_d·C(d,2)`; residues mod `gcd` of base weights `(d−2)`. Kills `(12,23,136)`'s unique profile (`3a_Q + 4b_Q = 20` forces `a_Q = 0` but `Σ_Q a_Q = 20`) and `3^1 4^2 5^19 7^1` at `(10,23,113)` (1,577 configurations, 1,380 K33-legal, minimum 39 > 18) [dfield26 P6]. Lean: `pairDeficit_add_sum_sub_two`, `sum_pairDeficit` (PairCounting.lean, ≈400 Mathlib lines) [dfield26 §5.2].

**P16 — Three-column incidence budgets and row-type kernels (dfield P7–P8).** Three distinct columns share `≤ 2` rows and `≤ 1` row pair (transpose K33-freeness); with `a_r = #` degree-`d` columns through row `r`: `Σ_r C(a_r,3) ≤ 2·C(n_d,3)`, `Σ_r C(a_r,2)·b_r ≤ 2·C(n_d,2)·n_{d'}`, plus pair versions with budget 1; used to bound row-type multisets (finite `omega` kernels, e.g. `(12,23,135)` `5^4 6^18 7^1`: minimum 25 > 15) [dfield26 P7–P8]. Lean: TripleIncidence.lean, ≈400 Mathlib lines.

**P17 — Penalty-line (supporting-line) classification (dfield P2; Afrasyab eqs. 5–6).** For any `α, β` with `p(d) := C(d,3) − αd + β ≥ 0` on `0..m`: `Σ_j p(c_j) ≤ 2C(m,3) − αw + βn`. It kills nothing P1 does not (it is P1 rewritten under `Σ c_j = w`) [afrasyab26 L2]; its value is a monotone prefix bound for histogram enumeration and an explicit, `omega`-provable finite profile list (dfield's `classify_*_degree_profile` theorems for ≤ 5 profiles; never for the 25 profiles of `(10,23)`) — i.e. it is a **cover-side** tool [dfield26 P2].

**P18 — Uniqueness-plus-extension closure (Hou Lemma 1; not a profile prune).** If `U = z(m,n−1)` exactly with extremal matrices classified up to permutation as `{R_1..R_k}` and `c = w − U` with `n·c ≤ w < n(c+1)`, then `z(m,n) < w` iff no `R_i` admits a degree-`c` column keeping it `K_{s,t}`-free; `k·C(m,c)` tests (924 at `(12,18,109)`) [hou2026_13x18 L3]. The uniqueness input is a nauty classification nobody has formalised; the pipeline's substitute is per-profile SAT + LRAT on the residual.

**P19 — Exactly-w thinning (cover side).** `Valid P A ∧ weight A > w → ∃ A' ≤ A entrywise, weight A' = w ∧ ¬HasKst P A'` (dfield `exists_submatrix_of_edgeCount_le` + `K33Free.mono`) [dfield26 §3.1] [afrasyab26 L10] [tan2022_sat L-delete]. Needed so the enumerator may list profiles of total exactly `w`. Lean: easy–medium, Mathlib-free.

**P20 — Monotone padding and zero-column reduction (cover side / conditional).** `z(m,n) ≤ z(m,n+1)` and `z(m,n) ≤ z(m+1,n)` by appending a zero column/row (Saurabh Lemma 2; the padded witnesses `A_{14×20}`, `A_{16×19}` are valid matrices *with a zero column*). Consequently "kill profiles with a zero (or `≤ 1`) column" — the `profiles.py` WLOG — is **not** a prune; it becomes one only when combined with a proved bound for the smaller cell (P5 with `c_j = 0`) [saurabh2026_five_lb P1–P3].

**P-codeg — codegree characterisation (bridge lemma).** `HasKst P A ↔ ∃ R : Fin s → Fin m, Incr R ∧ t ≤ Σ_j ind(∀ a, A (R a) j = true)`; connects the Python/SAT/GPU evaluators ("every row triple shares ≤ 2 columns") to the Lean definition; moderate, needed by every counting prune [bhan2026_lower_bounds L2] [padhi2026_gpu L4]. In the Mathlib route this is `hasKst_of_subsets` via `Finset.orderEmbOfFin` (COUNTING_SPEC).

**Explicitly not prunes (must be rejected by the gate and re-routed).** (i) Argument B (balancing): `C(m−1,k)+C(n+1,k) < C(m,k)+C(n,k)` for `m−n > 1`, so the A-sum is minimised by level sums — a statement about *which* partition is extremal, used for ordering and maximality, never for killing [tan2022_sat §3] [zarankiewicz_theory_counting P8]. (ii) Sorting partitions, lex order within equal-sum blocks, transposition when `a=b, m=n`, `sort_icdv`, the box-sum canonicalisation of `verifygraphs23.py`, dfield's canonical first column and row-stabiliser children: all additions with permutation witnesses [tan_kyoto_repo §11] [dfield26 "Not a prune"] [symmetry_breaking_matrices §7.2]. `Demo.notDescending_unsound` is the formal refusal; the project's E6 evaluator caught "kill any case with a row of sum ≥ 7" with an explicit realizable counterexample [experiments/LOG.md E6]. (iii) BCP/failed-literal refutation of a branch: sound, but it belongs to the `refuted` seam with a certificate, and failed-literal fixing is a RUP addition [alphamaplesat L1–L2]. (iv) Any hardness proxy: "a proxy weights a kill, it never justifies one" [sat_hardness_estimation §7].

### 3.4 What the catalogue says about where evolved prunes can act

Three facts from the census **[reproduced]** [zarankiewicz_theory_counting §5.2]: (i) Argument D is the big pair-level filter; (ii) Gale–Ryser and the dense cap add nothing on frontier cases; (iii) DGH (4) is the only *new* profile prune with teeth, and even it leaves 62,935 pairs at `z(13,18;3,3)`, `w=117`, and 85,582 at `z(16,16;3,3)`, `w=129`; `z(17;3)` at `w=141` has 573,049 pairs before D. dfield's experience says the same from the other side: at `(9,23,104)` the LP family cannot see the last contradiction and an *overlap* condition (P14) was needed [dfield26 P11]. Hence the baseline an evolved prune must beat is **A + A′ + D + D′ + I/deletion (with the best proved minor table) + DGH(4)**, and marginal kills must be measured against that baseline and weighted by difficulty, otherwise the search is rewarded for rediscovering dominated inequalities (Roman on profiles, Gale–Ryser, the dense cap) [zarankiewicz_theory_counting §7]. The room that remains is (a) cross-side arguments (P2 removes 82 % of pairs at `z(15,17;3,3)` and DGH's LP has no row/column coupling at all) [dgh2024_lp_bounds §12], (b) residue/overlap arguments of the P14–P16 family for `(3,3)` and their `(s,t)` generalisations, (c) Farkas combinations (P11) with an exact LP as oracle, and (d) enriching the case index beyond `(r, c)` (§10).

## 4. LP and counting bounds (Davies–Gill–Horsley) and their relation to the lemmas

**Roman's bound as an LP.** Roman's theorem is the optimum of the two-constraint LP over reals `n_{s−1}, …, n_m ≥ 0`: maximise `Σ i·n_i` subject to `Σ n_i = n` and `Σ C(i,s)·n_i ≤ (t−1)·C(m,s)` (DGH §1 misprints the objective as `Σ n_i`; §4 and the proof of Theorem 1.3 use `Σ i·n_i`, which is what reproduces the tables **[reproduced]**) [dgh2024_lp_bounds §3.1]. The optimum is piecewise linear in `n` with breakpoints ("Roman points") at `n = (t−1)C(m,s)/C(ℓ,s)`, attained iff an `s-(m,ℓ,t−1)` design exists; Čulík's theorem is the `k = s−1` piece [dgh26 §1].

**The new family.** For `1 ≤ v < s ≤ k ≤ m`, `α ≡ (t−1)C(m−v,s−v) (mod C(k−v,s−v))`:

`(1/(C(k−v,s−v) − α))·Σ_{i=s−1}^{k−1} (C(i−v,s−v) − α)·C(i,v)·n_i + Σ_{i=k}^{m} C(i,v)·n_i ≤ C(m,v)·((t−1)·C(m−v,s−v) − α)/C(k−v,s−v)` (DGH (4)).

The enlarged LP `E(m,n;s,t)` (GLPK/SageMath) lowers the best known bound by 1 (sometimes 2, once 3: `z(16,22;4,5) ≤ 239`) in a few hundred cells for `(s,t) ∈ {(3,3),(3,4),(3,5),(4,4),(4,5),(5,5)}`, `m ≤ 16`, `n ≤ 23`; `v = s−1` alone (`E*`) matches `E` in ≈97.5 % of cases (1697/1711 for `(3,3)`), and Roman's two constraints plus one `v = s−1` constraint give the closed form `B_k` of Theorem 1.3, proved by exhibiting dual multipliers `A, B, C ≥ 0` and pointwise checks `f(i) ≥ i`, `g(i) ≥ i` [dgh2024_lp_bounds §3–5]. Table 2 (`(3,3)`): `z(10,22) ≤ 111`, `z(10,23) ≤ 115`, `z(11,19..21) ≤ 108,112,116`, `z(13,17..21) ≤ 116,121,125,130,135`, `z(14,17..22) ≤ 124,…,150`, `z(15,17) ≤ 132` (by 2), `z(16,18..20) ≤ 146,152,158` (by 2). Two typesetting slips found **[reproduced]**: Table 6 row `m = 15` printed four columns left; Table 7 `(13,20) = 199` lacks its asterisk [dgh2024_lp_bounds §7].

**Relation to the lemma catalogue.** Constraint (3) is P1; the local inequality behind (4) with `v = 1` is P2 (Tan's Argument D), which DGH aggregate with rounding into the least useful member of their family but Tan uses pointwise on partition *pairs*, where it is strong — "complementary, not redundant" [dgh2024_lp_bounds §9]. (4) with `v = s−1` is P8, not implied by A, D, I. The LP itself is only a way of combining constraints; **per-branch checking on integer partitions is the integer program and is strictly stronger than the real LP**: requiring integrality lowers 30 more cells by one across DGH's ranges (`(3,3)`: `(10,23) → 114`, `(13,18) → 120`, `(14,19) → 134`), each verified by exhaustive enumeration with zero survivors **[reproduced]** — all now superseded in `(3,3)` by the 2026 exact values but still the model of "prune everything, run no SAT" [dgh2024_lp_bounds §8.2]. The LP is therefore useful in three ways only: as a cheap cell-level pre-check (`⌊E⌋ < w ⇒` skip), as a source of Farkas certificates (P11: multipliers plus a finite `decide` over sizes), and as a source of difficulty signals (min normalised slack over constraints, dual-weighted distance from the LP-optimal shape, which constraint binds) [dgh2024_lp_bounds §11]. It must never replace enumeration.

**Limits of degree-count LPs.** At `(9,23,104)` the DGH relaxation has exact optimum `314/3` at `n_4 = 31/3, n_5 = 38/3` and every integer profile satisfies its constraints; the last contradiction is an overlap condition on how nearly saturated triples meet individual rows [dfield26 P11]. Afrasyab's per-profile block-polytope LP (one variable per support, triple/row-link/pair capacities, one block fixed by symmetry) is strictly finer and separates 77 of 83 profiles at `13×22@138`, but the six survivors are exactly the near-balanced ones (penalty `≤ 19` of 83; the unique survivor at `139` has penalty 0) and needed marked-row leave enumeration plus Gram screens plus local Farkas certificates [afrasyab26 §4.3–4.6]. The pattern across all three sources is the same: **LP-infeasible profiles are the counting-easy ones; LP-feasible near-balanced profiles are where SAT or a genuinely new overlap argument is required.**

**Classical closed-form bounds** (KST, Reiman, Znám, Füredi, Čulík, Guy's exact region) are all consequences of P1 plus convexity and are dominated by P1 on a fixed profile; Füredi's Theorem 2 fixes `t−2` rows and counts `t`-subsets of their common neighbourhood, which uses codegrees and is not profile-checkable (its exact second-order terms could not be reconciled from the OCR-garbled scan) [zarankiewicz_theory_counting §2, P11]. Extremal structure: Roman equality forces a design; deleting the min-degree vertex propagates extremality (DHS 3.15); near-regularity is typical near Roman points but **not a theorem** — Héger's extremal `(8,8)` C4-free graph has degrees `{2,3,4}`, refuting the Illés–Krarup conjecture, and Héger's Questions 6.3.1–6.3.3 are open [zarankiewicz_theory_counting §2]. Guy's original letters `A–I` are supported only second-hand (A = binomial counting, B = balancing, C = deletion, D = row-local, E (code)/I (paper) = inclusion; F–H unverifiable) [zarankiewicz_theory_counting §1].

## 5. Difficulty estimation for branches

### 5.1 What "difficulty" means and what the sources measure

The proposal asks what "the difficulty of a branch" means. The consistent answer across the SAT literature is *solver work on an UNSAT instance* (seconds, conflicts, or unit propagations), and the consistent operational finding is that **nobody estimates it without running something**: static formula features add little beyond cheap probes (Hutter et al. 2014, Table 3: models using at most moderately expensive features are statistically indistinguishable from the full 138-feature set; cheap features often suffice; accuracy ceiling RMSE ≈ 0.5 in `log10`, i.e. a factor ≈ 3) [sat_hardness_estimation §3.1]. Hardness in a case split is **heavy-tailed**: Keller `s=6`: 38,616 subformulas, average 7.63 s, 63 needed > 900 s, hardest ≈ 1.25 CPU-h; Codish `R(4,3,3)`: per-degree-triple averages from 51 s to 1554 s and one triple with 3,105 instances accounts for 253 of 358 CPU-h; Codish's degree-matrix instances: median 4 h, mean 14 h, max 96 days over 78,892 same-shape instances [sat_hardness_estimation §3.3, §3.8] [symmetry_breaking_matrices §4]. AlphaMapleSAT's whole gain over `march_cu` is explained by fewer *very hard* cubes (> 5000 s): at `KS21` cutoff 80, march ≈ 44 hard cubes vs AMS ≈ 2, and the hard tail dominates wall clock [alphamaplesat §6]. dfield's `(10,23)` data show hardness is **not monotone in counting slack**: the two largest direct proofs had slacks 22 and 15, the VIPR-B profile slack 3; the three profiles that defeated direct CaDiCaL all had one degree-3 column plus balanced degree-4 and degree-6 blocks [dfield26 §8.1]. Two consequences for the reward: weight kills by estimated work, never by count; report the tail (kills among the hardest decile) alongside the sum [alphamaplesat §8.4] [chivilikhin2023_decomp §6.2].

Proof complexity adds a twist that is the thesis's value proposition: resolution (hence CDCL) needs exponential refutations of pigeonhole-type cardinality contradictions while cutting planes refute them polynomially, so a branch that is empty *for a counting reason* can be very expensive for CaDiCaL yet trivial for a Lean-checked counting lemma; "hard for the solver" and "killable by a short proof" are not opposites, and such branches are the highest-value kills [sat_hardness_estimation §3.6].

### 5.2 Sampling estimators (Chivilikhin–Pavlenko–Semenov)

Decomposition hardness `μ_{B,A}(C) = Σ_β t_A(C[β/B])`; Theorem 2: `μ = 2^{|B|}·E[ξ_B]` for `ξ_B` = work on a uniformly random cube (`A` deterministic); estimator `μ̃ = (2^{|B|}/N)·Σ_j ξ^j`; Theorem 3 (Chebyshev): `N ≥ Var(ξ)/(ε²·δ·E²[ξ])` gives an `(ε,δ)`-approximation, with the practical doubling rule from `N = 1000` [chivilikhin2023_decomp §3]. Unit propagations and conflicts are statistically indistinguishable as workload measures; wall-clock is worse (`p = 0.043`) [chivilikhin2023_decomp §4]. In natural decompositions almost every piece is UP-trivial (`ρ ≈ 1` already at `|B| = 20`), so an incremental UP-only solver measures the trivial cubes and only hard cubes go to the full solver; the `ρ`-backdoor fraction is Bernoulli (`Var ≤ 1/4`), hence cheap to estimate with `N ≈ 150–250` regardless of heavy tails. The identities transfer verbatim one level up: with `S` the survivor set and `ξ_S(q) = t_A(C_q)` for `q` uniform on `S`, total remaining work `W(S) = |S|·E[ξ_S]`, estimated from a **shared** sample of survivors so that candidate prunes are compared with common random numbers and each new candidate costs only `N` `kill` calls [chivilikhin2023_decomp §6]. Their "pairs and triples of backdoors beat singles" (Table 2; simulated speedups ≈ 70–85× at 32 threads with triples) is Tan's row × column split with an argument for a third split axis [chivilikhin2023_decomp §4, §6.5].

### 5.3 Ranked implementable proxies

All proxies are functions of the branch CNF alone, computable once and cached, hence independent of the candidate prune and ungameable by its text [alphamaplesat §8.4] [sat_hardness_estimation §6]. Costs refer to `z(10,14;3,3)` (6.5k vars). The ranking uses the project's pilot on 14 recorded column profiles at weight 78 (all UNSAT, CaDiCaL 9–363 s, four censored) [sat_hardness_estimation §5], which is `n = 14`, one instance size, one solver — a pilot, not a conclusion.

Not recommended: strong-backdoor size (`r = 0.71–0.78` but exponential to compute), weak backdoor size (`|r| ≤ 0.13`), static graph/balance features (constant within an instance), full LP relaxation of the CNF [sat_hardness_estimation §3.5, §6]. Symmetry-derived signals worth logging: residual stabiliser size `Π|R_v|!·Π|C_u|!` (dfield's hardest profiles had `5^18`, `5^16`, `5^14` blocks), number of canonical prefixes/orbits, one-sidedness (all row sums distinct ⇒ the lex chain is complete) [symmetry_breaking_matrices §9]. Static profile features (KST slack, max weight, distinct weights) are good prunes but poor rankers on the same 17-sample data [alphamaplesat §8.3].

**Suggested composite** [sat_hardness_estimation §6]: `hardness(r,c) = P1` if refuted within the cap, else a monotone calibration of `(P2, P3, P4, P5)` fitted on training-ladder cells where P1 finishes (Haim–Walsh style, validated by RMSE in log units on held-out cells; expect a factor-3 ceiling), clipped to `≥ cap`; reward for a verified prune `= Σ_{killed} hardness / P6-estimate of the table's total`, with the top-decile tail reported alongside. Choose the cap on target cells so that a sampled quantile (e.g. 70 %) of survivors finishes (Heule's practice) — below that the censored count carries no ranking information. Keep the DRAT/LRAT proof of every branch the probe refutes so probing is amortised into the `refuted` seam.

Other measures the proof-search literature suggests [llm_lean_provers_2026 §6]: AlphaProof's return is the *minimum* over AND-subgoals (a case's difficulty is its hardest sub-cube, not the sum); Seed-Prover scores lemmas by proof rate under a fixed budget ("lemmas with low proof rate are often crucial"); Goedel/Seed/Kimina curricula keep pass rates in `(0, 0.75]` / `> 1/4` excluded — the analogue is presenting the LLM with branches in the painful-but-finite band.

## 6. Formal verification: the Lean gate, certificates, sandboxing, prune-vs-add

### 6.1 The gate as it exists

ZarPrune (Lean 4.34.0) accepts a candidate exactly when it elaborates as a term of `Prune P` (`kill` + `sound`); "there is no third outcome and no trusted escape hatch" [lean/README.md]. The trusted core (`Sum/Basic/Prune/Prunes.lean`) is Mathlib-free, builds in well under a second, and depends only on `propext` and `Quot.sound`. Measured (E4/E5): 0.3–0.5 s per standalone candidate including a Lean-side `#eval` of the kill mask on up to 725 cases; ~1.3 s for a four-instance suite in one process; 1.8 s with targeted Mathlib imports; `leanchecker` on ZarPrune 0.66 s, `--fresh` 29.4 s [experiments/LOG.md E4–E5] [lean_verified_sat_and_sandbox §10.1]. "Does Lean take too long?" is answered: no — an LLM generation costs 30–120 s, a Lean check well under two seconds, a SAT probe more than both [reward_shaping_proof_tasks §0]. The gate has two independent layers: a source scan (`sorry`, `native_decide`, …) and an axiom audit (`#print axioms`); a `sorry` that slips past the scan still fails the audit (`sorryAx`) and Lean refuses to `#eval` a term depending on it [experiments/LOG.md E4].

### 6.2 Discharging `refuted`: verified LRAT checking

Lean 4.34 core ships a verified LRAT checker: `Std.Tactic.BVDecide.LRAT.check : Array IntAction → CNF Nat → Bool` with `check_sound : check proof cnf → cnf.Unsat`, parsers for text and binary LRAT, and `Reflect.verifyCert(_correct)`; full RAT is supported [lean_verified_sat_and_sandbox §2.1]. A branch theorem is `LRAT.check_sound proof cnf (by native_decide)`, which since Lean 4.29 records **one fresh axiom per evaluation** named `<decl>._native.native_decide.ax_k : check proof cnf = true` (`ofReduceBool`/`trustCompiler` are deprecated since 2026-02-01); kernel-only checking (`decide +kernel`) is impossible because the checker's loop is well-founded recursion marked `@[irreducible]` (stuck even on PHP(3,2)), and Mathlib's `lrat_proof` is RUP-only and runs out of memory at 63 MB [lean_verified_sat_and_sandbox §2.3–2.4]. Measured locally: a 151 MB / 1.13 M-line LRAT for the K22-free 7×7 instance imports in 16 s / 2.35 GB; LRAT-Catcher reports ≈ 140–150 CPU-s per GB and memory `2.05 GB + 0.28 GB/GB` of largest leaf, ≈ 15× slower than `lrat_isa`, comparable to `cake_lpr`; Keller ITP 2026: check ≈ 0.5–1× solve [lean_verified_sat_and_sandbox §3.4]. The toolchain bundles CaDiCaL 2.1.2 and `leanchecker`; DIMACS literal `±k` ↔ Lean variable `k−1`; CaDiCaL ≥ 3.0.0 needs `--no-factor` (extension variables are silently skipped); Kissat 4.0.x emits DRAT only (`drat-trim -L`). `bv_decide` alone (verified bit-blaster + LRAT, no encoding proof) proves `z(n,n;2,2)` bounds up to `n = 7` in 20 s — a zero-encoding-proof oracle for tiny branches [lean_verified_sat_and_sandbox §10.5].

The remaining obligation is **encoding completeness**: `Valid P A → profileOf A = q → (encode P q).Sat (assign A)`, only the direction needed for refutation (easier than Codel–Avigad–Heule's `encodes` iff). Precedents: Codel–Avigad–Heule FMCAD 2023 (Lean 3 + mathlib; `is_wb` well-behaved encodings compose; verified parity/AMO/sequential-counter AMK), Trestle's `VEncCNF`/`withTemps`/`for_all` used in Keller (full encoding verified in 150 lines; `cliqueToAssn_satisfies_fullSpec` is exactly the object-to-assignment shape we need), Lean core's own verified Tseitin `toCNF_equisat`, Empty Hexagon (verified encoder but `cake_lpr` verdict asserted as an axiom), LRAT-Catcher's `lrat_reflect_cnf`, PBLean, and Gocht et al.'s certified CNF translations of cardinality constraints in VeriPB (direction UNSAT(CNF) ⇒ UNSAT(PB)) [lean_verified_sat_and_sandbox §5]. For ZarPrune the realistic route is a home-grown `Encode.lean` over `Std.Sat.CNF Nat` with witnesses for auxiliary variables — sequential counter (prefix sums) is cheaper to prove than the totalizer; choose the encoding by proof cost, not solver speed. The project's E9 pipeline (`cadical --binary=false` DRAT → `drat-trim -L` → `lrat-check`) already certifies all 36 survivors of `(9,9,50)` in 1.8 s with 3.8 MB of LRAT; its stated trusted base is the CNF encoding and the partition generator's completeness [experiments/LOG.md E9]. Neither Tan (DRAT never checked; exit ≠ 10 = UNSAT) nor Padhi (no proof logging; false UNSATs) nor dfield (LRAT checked externally, never in Lean) closes this seam in Lean; doing so is a genuine step beyond all three [tan_kyoto_repo §6] [padhi2026_gpu §6] [dfield26 §5.5].

### 6.3 Sandboxing rules for LLM-written Lean

The official validation ladder: kernel acceptance → `#print axioms ⊆ {propext, Classical.choice, Quot.sound}` (`_native` names mean native evaluation) → `leanchecker`/`lean4checker --fresh` (catches environment hacking; reads `.olean` without validating format) → `lake comparator` (Linux-only `landrun` sandbox, `lean4export`, kernel + `nanoda`; `--paranoid` adds `leanchecker-paranoid`, `lean4lean`, `con-leche`) [lean_verified_sat_and_sandbox §4.1]. Measured escape hatches: `axiom spoof._native.native_decide.ax_1_1 : False` compiles, is printed by `#print axioms`, and **passes `leanchecker`** (it does not re-evaluate native axioms); lean4 issue #7463 (`@[csimp]` smuggling) is open; `autoImplicit` defaults to `true` in core (typo variables become universally quantified); "Faults in Our Formal Benchmarking" reports proofs of False from native-code bugs and `implemented_by` overrides [lean_verified_sat_and_sandbox §4.3, §10.4]. Hence two trust domains: **LLM prune modules** must contain zero axioms of any kind, pass a source blacklist (`axiom`, `sorry`, `native_decide`, `+native`, `implemented_by`, `extern`, `csimp`, `unsafe`, `partial`, `opaque`, `set_option`, `#eval`, `#exit`, `initialize`, `macro`/`notation`/`syntax`/`elab`, `run_cmd`, any `import`, `open Lean`, `IO.`, `ofReduceBool`, `trustCompiler`), be compiled from source in a sandbox with time/memory limits (never accept an LLM `.olean`), have the statement owned by a harness wrapper (`def evolved_<id> : Prune <P> := <name>` in a file the LLM cannot edit, referring to `ZarPrune.Valid` etc. by full name, `autoImplicit = false`), pass `leanchecker`, and have `kill` `#eval`-able; **harness refutation modules** may carry `_native` axioms whose names the harness recorded at generation time and re-matches [lean_verified_sat_and_sandbox §4.4]. SafeVerify does replay + declaration matching + axiom check but "does not check for keywords like `implemented_by`, `extern`, or `noncomputable`". Every bound row should list its axiom ledger (`{propext, Quot.sound}` for Lean-only prunes; `+ k` native-evaluation axioms for `k` refuted branches; `+ 1 cake_lpr` axiom if the fallback is used), as LRAT-Catcher Table 5 and Empty Hexagon report [lean_verified_sat_and_sandbox §9].

The reward-shaping survey adds the *content* threats: vacuity (`kill ≡ false` elaborates and must score 0), triviality (kills only what the baseline kills), and redefinition of `Valid`/`HasKst`/`Params` inside the candidate file (a Kimina/Vericoding-style "exploit the formalization" move) [reward_shaping_proof_tasks §2.6]. The NL↔Lean statement-fidelity problem that dominates autoformalization (60.7 % of compiling FormalMATH statements semantically wrong; 3–29 pp compile–faithfulness gap) is solved *by construction* for prunes because the harness fixes the statement; it re-appears only if the LLM were ever allowed to author the encoding-correctness or cover-completeness theorems — it must not be [reward_shaping_proof_tasks §2.6].

### 6.4 Pruning versus adding, and the `cover` seam

Clausal proof systems distinguish **implied** clauses (RUP: `F ∧ ¬C ⊢₁ ⊥`, no witness) from **redundant** clauses that only preserve satisfiability and need a witness: RAT (pivot), PR (partial assignment; Heule–Kiesl–Biere Thm 1: `C` redundant iff `∃ω ⊨ C` with `F|α ⊨ F|ω`), SR (Buss–Thapen Def 1.13: substitution `τ ⊨ C`, `Γ|α ⊢₁ Γ|τ`; Thm 1.15 equisatisfiability; a permutation is a legal witness since `Γ|π = Γ`), VeriPB redundance (Def 6) and dominance (Def 13: the witness need only reach a *strictly smaller* assignment in a fixed preorder; lex-leader for any symmetry `σ` derived once as `C_LL = Σ 2^{m−i}(σ(x_i) − x_i) ≥ 0`; "handling a symmetry once is enough") [lean_verified_sat_and_sandbox §6.1] [symmetry_breaking_matrices §6]. Symmetry-breaking predicates are the canonical redundant clauses: Heule–Hunt–Wetzler needed definitions + clause redefinition + sorting networks to express them in DRAT, and even a 3-cycle "brings us beyond what DRAT-based proof logging symmetry breaking is currently able to handle" [symmetry_breaking_matrices §6.1]. Cube-and-conquer adds the third obligation, the **tautology proof** that the cubes cover the space (Pythagorean triples; LRAT-Catcher Lemma 17 `cover_unsat`) [lean_verified_sat_and_sandbox §6.2].

Mapping onto ZarPrune: `Prune.sound` is the implied side (`F ∧ cube_q ⊨ ⊥`); `refuted` is the leaf UNSAT; `cover` is the tautology obligation; "assume rows sorted", column lex and `row_degmono` are the redundant side and can never be `Prune`s. Keller's rule for where the seam goes: prove in Lean the WLOG steps the certificate language cannot express, put the transition point as early as possible, and let SR/LRAT do the rest [lean_verified_sat_and_sandbox §6.3].

**Symmetry facts that matter for fixed-sum cases** [symmetry_breaking_matrices]: (i) full lex-leader over `S_m × S_n` is complete but NP-hard to check, and a poly-time complete SBP for row–column symmetry would put GI in coNP (Anders–Brenner–Rattan 2024) — so no compact complete break exists; (ii) double-lex is sound by Flener's potential argument, whose proof only swaps interchangeable pairs, so **block-wise double-lex is sound for the case stabiliser** `G_q = Π S_{R_v} × Π S_{C_u}` (Tan's Theorem 3.2 partition clause); (iii) it is **incomplete exactly in our regime** — KNW Thm 2 leaves `n!` symmetric solutions in a `2n×2n` class with row/column sums in `{1,2}`, Tan's Fig. 2 shows two isomorphic survivors; (iv) BreakID Thm 2: an adjacent-row lex chain under a matching row-major order breaks a *pure* row-interchangeability group completely, so with only column sums fixed (dfield) the row group is completely broken, whereas with both sums fixed (Tan, ZarPrune) two factors are each only partially broken; (v) mixing linearisations (row-major double-lex with snake-lex, or opposite directions for rows and columns) can delete every solution of a class (KNW Thm 6/7). Codish et al.'s `sb*_ℓ(A, M)` with its theorem "there exists `A′ ≈ A` with the same degree matrix satisfying the break" is exactly the shape of an in-case ADD theorem [symmetry_breaking_matrices §4].

**Two seams for additions** [symmetry_breaking_matrices §8]: (A) `cover` generalised to `kill ∨ ∃ q ∈ survivors, ∃ σ τ, profileOf (act σ τ A) = q` (orbit representatives: sorted profiles, transpose when `m = n, s = t`), needing a Mathlib-free `Perm`, `act`, `sumFin_perm`, and the one hard lemma `HasKst_act_iff` (re-indexing an injective tuple to an increasing one; shared with P1's extraction lemma), then `upper_bound_of_cover_upto_perm`; (B) `refuted`, either B1 (emit lex clauses as SR/dominance steps with permutation witnesses, checked by Trestle/CakePB/PBLean outside the `Prune` type; no solver emits SR yet, so the generator writes the prefix and the checker validates the concatenation) or B2 (prove once in Lean `exists_doubleLex : profileOf A = q ∧ Valid P A → ∃ A', profileOf A' = q ∧ Valid P A' ∧ DoubleLexBlocks q A'` by strong induction on `Σ 2^{i+j} − pot A`, ≈250–400 lines, after which an LRAT refutation of `CNF(q) ∧ Lex(q)` discharges `refuted q` with an ordinary encoding lemma). Recommendation: B2 for the standard block double-lex, B1 for case-specific symmetries the search may discover (canonizing sets, cube covers). `cover` itself is best discharged by a decidable enumeration proof over bounded profiles (no solver), switching to the negated-cube LRAT form only if cubes come from a solver-driven splitter [lean_verified_sat_and_sandbox §7.2–7.3, §9]. The trust-policy conflict must be resolved explicitly: every scalable reflective importer (core LRAT via `bv_decide` machinery, PBLean) rests on native evaluation, which `lean/README.md` currently forbids; the options are relaxing it for the `refuted` seam only (auditable via named `_native` axioms), explicit proof terms (does not scale), or external verified checkers with imported verdicts [symmetry_breaking_matrices §6.3].

## 7. LLM + Lean state of the art, and direct-Lean versus two-stage

### 7.1 What the systems do

Every serious Lean prover surveyed trains on a **binary kernel reward** and none scores sorry-count or remaining goals at the terminal step: DeepSeek-Prover-V1.5/V2 (1/0), Kimina (1/0, format ⇒ 0), Goedel-Prover-V2 (binary, pass-rate window `(0, 0.75]`), Seed-Prover 1.0 (1/0 + formatting penalty), Seed-Prover 1.5 (+1/−1), Leanabell-V2 (`R_format 0.2` vs 1.0), AlphaProof (`r_t = −1` per tactic, return = min over AND-subgoals) [llm_lean_provers_2026 §4 Q3] [reward_shaping_proof_tasks §3]. The only dense Lean-derived reward with a controlled ablation is Process-Verified RL (tactics before the first error `−0.05`, after `−0.1`, verified `+1`, first-error propagation): +2.5 pp miniF2F, +1.2 pp ProofNet over outcome-only GRPO — real but small [reward_shaping_proof_tasks §2.2]. Partial progress is instead cached (lemma pools), converted into new statements (`extract_goal`, TTRL variants), or used as a search heuristic (value heads, LeanProgress) [llm_lean_provers_2026 §4 Q3].

On Q1 (direct Lean vs NL sketch): step-level searchers emit tactics directly (AlphaProof's 3B policy/value network with AND-OR MCTS, ≈80,000 TPU-days; Aristotle's MCGS with a >200B model, hidden CoT, negation branches for disproof), whole-proof RL provers write Lean after a long NL/Lean-interleaved CoT (DeepSeek-V2: CoT mode +7.6/+8.6 points at pass@32 for ≈10× tokens), and the **sketch-and-fill lineage** (DSP → DeepSeek-V2 cold start → DSP+ → Hilbert → Seed-1.5 sketch model → Goedel-Architect → Aristotle's lemma pipeline) has the reasoning model emit the informal proof *and* the Lean skeleton with `have … := by sorry` holes in one call, compiles the statements immediately, and fills holes with a prover in a compile loop [llm_lean_provers_2026 §4 Q1]. 2026 agentic harnesses put frontier general models directly on Lean with REPL/LSP tools (Numina-Lean-Agent 12/12 Putnam 2025 with Claude Opus 4.5; MerLean; Leanstral 1.5; Seed-1.5's agentic prover with ≤ 28 tool calls), and the UW controlled study shows zero-shot Gemini 3.1 Pro at 92 % and Claude Opus 4.7 at ≈86 % refine@32, obsoleting the April-2025 picture (o3-mini 24.6 %, Gemini 2.5 Pro 37.7 %) [llm_lean_provers_2026 §2.13].

On Q2 (loops): Kimina one fix turn (84.0 → 86.4 pass@32; 16+16 attempt-and-fix 35.6 % vs 32×1 28.8 % on the 59 hardest); Goedel-V2 two rounds (+≈2 pts; five rounds with 128k context 92.7 % pass@32 > 92.2 % pass@8192; ablation: removing compiler error text "significantly lowers performance", removing previous CoT slightly hurts); Seed Light 8–16 refinements (≈ Pass@64–256), Medium adds an 8×8 inner loop (PutnamBench 201 → 331); Hilbert 6 correction passes per subgoal, depth 5 (75 % → 99.2 %); UW refine@32 averages +7.7 on miniF2F but −1.4 on miniCTX (helps large-context frontier models, hurts small ones); APRIL 4–8B models repair ≈30 % single-shot from diagnostics [llm_lean_provers_2026 §4 Q2]. Consistent findings: the *specific* error text matters; gains saturate in 2–5 rounds; context hygiene (cap error text, self-summaries) matters.

On Q5 (split): the reasoner is the lever for sketches (Hilbert: Flash → Pro moves 94.7 → 99.2 with the same prover; gpt-oss-120b → Pro moves PutnamBench 88 → 462; DSP+: removing the drafter hurts most; DeepSeek-V3 sketch + 7B filler ≈ 671B end-to-end), while a cheap model with a compile loop fills holes (Goedel-V2 8B + 2 rounds 86.7 % beats DeepSeek-V2 671B without a loop 82.4 %); cost frontier Goedel-Architect at $0.44/problem (DeepSeek-V4-Flash architect + tool prover) vs Hilbert ≈ $244; every pipeline tries the cheap path first and escalates to the reasoner for *re-decomposition*, not retries [llm_lean_provers_2026 §4 Q5].

### 7.2 What transfers to this thesis, and what does not

Access (checked live 2026-09-21): no specialised prover is usable by API — `deepseek/deepseek-prover-v2` is listed on OpenRouter but returns "No endpoints found"; Kimina/Goedel/Leanstral are not on OpenRouter; Seed-Prover, Aristotle and AlphaProof are closed. The open provers were trained on Lean 4.9–4.22 Mathlib snapshots; **no surveyed system has seen Lean 4.34 or a Mathlib-free environment**, and the UW study shows specialised provers collapse by > 20 points on unfamiliar contexts (miniCTX). The realistic path is frontier general models via OpenRouter (Gemini 3.1 Pro $2/$12 per M tokens, Claude Opus 4.7 $5/$25, GPT-5.4-mini $0.75/$4.5, GPT-OSS-120B $0.15/$0.60, DeepSeek-V4-Flash $0.06/$0.11) with an explicit list of available vocabulary and a compile loop [llm_lean_provers_2026 §4 Q4, §5.2]. Since E5 the candidates may use targeted Mathlib imports (`Finset`, `Nat.choose`, `BigOperators`), which materially reduces the vocabulary gap that the reader flagged for the Mathlib-free core (`Nat.choose`, `nlinarith`, `norm_num`, `Finset` absent from core) [llm_lean_provers_2026 §5.2] [experiments/LOG.md E5]; `omega`, `decide`, `grind`, `obtain`, `rintro`, `simp`, `rw`, `Fin.cases` are in core.

The gate is already the right object for sketch-and-fill: the statement of `sound` is fixed by the harness (the UW "structural extraction" and Kimina "theorem consistency" safeguards come for free), so a reasoning model should emit (i) the NL counting argument, (ii) the executable `kill` over `Profile`, and (iii) a `sound` skeleton with typed `have … := by sorry` holes in one call; Lean checks (ii) and the hole statements in under a second; a cheap model runs 2–3 compile/fix rounds with the exact message, position and goal; on exhaustion, one escalation to the reasoner asking for re-decomposition [llm_lean_provers_2026 §5.1, §5.3]. Verified-prefix (fraction of `have` bodies that elaborate without `sorry`, truncated at the first error) is the one safe sub-verified score and only as a tie-breaker among unverified candidates; never let an unverified candidate outrank a verified one. Budget: with ≈ $16 the reasoner is called O(10) times for sketches at $0.06–0.13 per call and the loop runs on a sub-cent model (the Goedel-Architect split) [llm_lean_provers_2026 §5.2]; the lower-bound paper's own numbers (≈ $0.05–0.10 per iteration, $15–30 per case) confirm the budget buys probes, not a run [bhan2026_lower_bounds §8].

The proposal's two-stage question therefore has a specific answer from the evidence: **not** "NL then a separate autoformalizer" (the autoformalization literature shows compile ≠ faithful, and here the statement is fixed anyway), but "reasoning model writes NL + `kill` + typed skeleton; cheap model fills holes under compiler feedback; the harness owns the theorem". A lemma pool of accepted prunes and helper lemmas (Seed's lemma pool, Aristotle's proven-background blocks, LEGO-Prover's 24 % skill reuse) is the only form of partial progress the literature retains across attempts and is naturally carried by OpenEvolve's artifact channel [reward_shaping_proof_tasks §2.5].

## 8. Evolutionary mathematical discovery and reward-design lessons

### 8.1 The loops

FunSearch pairs a pretrained LLM with an evaluator, evolves a priority function inside a fixed skeleton ("focuses the LLM resources on only evolving the critical part"), uses islands reset every 4 h, Boltzmann cluster sampling with decaying temperature, and prefers shorter programs; the cap-set 512 was found in only 4 of 140 runs, and the discovered program was interpretable enough to yield an explicit symmetric construction [alphaevolve_and_math_discovery §1]. AlphaEvolve evolves whole files with an `evaluate` function returning a dictionary of scalars, MAP-Elites + islands, Flash/Pro ensembles, evaluation cascades, LLM-graded auxiliary scores, and four genome levels: raw object, constructor function, bespoke search algorithm under a compute budget, or co-evolved (object, improver); its combinatorial records mostly used **search mode** — "the score of the heuristic is the score of the best object it finds" within a time budget starting from the previous best — and its verification is exact recomputation (integer/half-integer rounding; 593 integer points + a one-paragraph lemma for the kissing number), never a proof assistant [alphaevolve_and_math_discovery §2]. Tao–Wagner (67 problems) confirm search mode was "the standard mode", add **generalizer mode** (score one program over many `n`, show only small `n`: "less is more"), and give the evaluator lessons that matter most: "the selection of the verifier is a critical component"; continuous losses beat discrete counts; a "cheating phenomenon" appears with leaky verifiers ("it always eventually figured out a way to cheat"); use a fast floating verifier for search and an exact rational one for claims; cheap models across many runs cost "a few USD" on easy problems but fail on hard ones; mixed ensembles add useful variance [alphaevolve_and_math_discovery §3.3, §3.5]. Cloud AlphaEvolve (GA 9 Jul 2026) exposes exactly this contract (`scores: [{metric, score}]` all maximised, ≤ 10 `{label, text}` insights, `EVOLVE-BLOCK` markers, 30-minute evaluation lock, no cascade, pricing undisclosed), and SkyDiscover's `evaluate(program_path) → {combined_score, artifacts}` is byte-compatible with OpenEvolve's evaluator, making AdaEvolve/EvoX a drop-in ablation backend (its benchmark claims are self-reported; 2 of 8 math tasks were not matched) [alphaevolve_and_math_discovery §5–6].

**Lean was never inside any construction-evolution reward loop.** Tao–Wagner used AlphaProof only post hoc (one Kakeya instance, "possible only when the proof was simple enough; in particular all of its necessary steps needed to have already been implemented in the Lean library mathlib") and name "AlphaEvolve first finding the candidate, then providing the e.g. Lean code of such computer-assisted proof to validate it, all in an automatic fashion" as future work; Nagda et al. evolved a 10,000× faster verifier but re-verified final gadgets by brute force. Lean kernels do sit inside *proof-search* evolution: DeepMind's AlphaEvolve-inspired sketch-evolution agent (9/353 open Erdős problems, "a few hundred dollars per problem", LLM-rater Elo for unfinished sketches) and ProofEvolve (kernel-verified closure fraction of AND-OR proof DAGs as graded fitness; credit only for what the kernel accepted) [alphaevolve_and_math_discovery §3.4, §4]. The thesis's in-loop gate targets precisely the gap Tao–Wagner name.

### 8.2 The lower-bound predecessor and its reward

Bhan et al. evolved programs returning `(G1, G2)` with Nagda et al.'s Ramsey recipe (ones ×4 if beating the running record `n_SoTA`, ×2 tie, ×1 otherwise, −1 on violation; a prospect-matrix bonus `½·max(0, 1 − viol/E_viol)`), three 100-iteration phases with Flash/Sonnet then Flash/Opus mixes, population 60–70, 4–5 islands, full rewrites, artifacts (the record matrix with degrees) in the prompt; $15–30 per case, ≈ 10 min per phase, 21 s/iteration, evaluation 50 ms [bhan2026_lower_bounds §4–8]. The code analysis shows the reward is a non-stationary cliff (one edge = 4× score, dependent on evaluation time), the G2 term is worth less than half an edge and was gamed by `G2 = G1.copy()`, and the artifact channel turned program evolution into matrix-level local search (hard-coded record matrices; rip-up-and-repair) [bhan2026_lower_bounds §4.1, §9]. None of this broke the lower-bound search because validity is exact and cheap; it would break an upper-bound search where "validity" is a Lean proof. The record profiles (`(11,21)=116`: rows `11^6 10^5`, cols `6^11 5^10`; `(12,22)=132`: rows `11^12`, cols `6^22`) are exactly the profiles no prune may kill at those weights — a free negative test [bhan2026_lower_bounds §7.2, L3].

### 8.3 Reward-design lessons, ranked by evidence

Tier A (multiple sources) [reward_shaping_proof_tasks §6]: (A1) binary verification is the reward and the difficulty band is the curriculum — score 0 unless `Prune P` elaborates clean with the standard axioms, then score marginal kill-mass; choose the sub-task (instance `P`, restriction `S`) so the verified rate stays in `(0, 1/2]`; (A2) the six-level Lean status ladder (L0 parse fails … L3 sorry-sketch … L5 verified) as a MAP-Elites axis and prompt-feedback source, never the main reward; (A3) feed the first error and remaining goal text back, two repair rounds; (A4) sorry-decompose failed proofs into `have` targets with core-tactic auto-fill; (A5) vacuity and triviality checks before Lean; (A6) novelty rejection on the kill signature (Jaccard > 0.95) and phenotype clustering (FunSearch signatures). Tier B: first-error depth as a ≤ 5 % tie-breaker; count/curiosity-based cell selection (Go-Explore `counts^−0.5`, Cully +1/−0.5), CMA-ME "new cell beats improvement" insertion, FunSearch island resets — OpenEvolve has islands, custom feature dims, 0.2/0.7/0.1 sampling and an embedding novelty gate, but uniform parent sampling and no resets [reward_shaping_proof_tasks §4.3]; weaker-statement credit via `Prune.restrict`/`Prune.mono` (4-line lemmas); a lemma ledger with usage-based credit; the empirical soundness gate on known valid matrices; difficulty-weighted mass via censored probes. Anti-proposals: no partial credit for `sorry` proofs that kill mass; no LLM judges as reward (QDAIF correlation collapses near quality 1.0); no reward for code length or lemma count.

A concrete evaluator formula that follows [reward_shaping_proof_tasks §7]: `combined_score = 0` if unsound on the witness battery, fires on no case, or status ∈ {L0, L4}; `0.15·ladder + 0.05·depth` for L1–L3 (capped at 0.20); `0.20 + 0.80·m_new/m_tot` at L5 with `m_new` the marginal difficulty-weighted kill mass over the accepted library; feature dimensions `[kill_mass_marginal (log-binned), lean_status]`; cascade stage 1 = parse + kill mirror + vacuity + witness battery, stage 2 = Lean, stage 3 = full-enumeration mass + probes. The project's evaluator already implements the battery (E6 caught an unsound candidate with a realizable counterexample) and learned that the scoring baseline must equal what is *proved in Lean*, not what the Python case builder applies, or proving Argument D would earn nothing [experiments/LOG.md E6].

Genome level for prune discovery [alphaevolve_and_math_discovery §8.3]: G1 constructor mode (evolve `kill` + proof directly; interpretable, low throughput), G2 search mode (evolve a Python program that searches a parametric family of counting inequalities against a counterexample bank; the evaluator instantiates a fixed Lean template — the "one slow LLM call → millions of cheap checks" leverage), G3 generalizer mode (score across several `(m,n,s,t)`, show only small instances; proofs must be over symbolic `Params`), G4 co-evolution (pay Lean once per lemma family, explore parameters at zero Lean cost). Tao–Wagner's finding that "prompting as in our search mode … resulted in more efficient programs and much better results" argues for G2/G4 as the default; G1 is what the thesis's interpretability goal wants for the *final* artefact.

## 9. Closest prior work (dfield) and what this thesis adds

dfield/finite-zarankiewicz-closures [dfield26] is the only existing pipeline that combines profile enumeration, arithmetic kills, SAT/MIP on survivors, and Lean. Its structure: reduce to exactly `w` ones; enumerate column-degree histograms under the triple capacity via a penalty line (3 at `(9,23,104)`, 25 at `(10,23,113)`); kill by deletion against neighbour bounds, marked-row residues, pair-deficit residues, three-column budgets and row-type kernels (P5, P14–P16); per-profile CNF with `y_{T,j}` indicators and AtMost2 per row triple, `Exactly(d_j)` per column, double-lex on rows and equal-degree columns, a min-row-degree cut (≈ 10.9k vars / 22.4k clauses), CaDiCaL `--unsat -P2` with DRAT → LRAT → `lrat-check`; one profile needed a 17,170-leaf canonical row-stabiliser cube cover (16.5 GB), two needed row-symmetry orbit covers (209 and 236 orbits over 295,001 and 950,250 states) solved as exact SCIP MIPs with VIPR certificates; ≈ 25.3 GB of certificates, ≈ 9 days on a 48-vCPU AWS cluster, no solver times published [dfield26 §3, §6]. Lean 4.29 + Mathlib (17 files, 4,896 lines) formalises the matrix model, all counting/deficit/deletion identities, kernel-checked witnesses, and end-to-end theorems for `(9,23)`, `(10,22)`, `(12,23)`, `(13,23) ≤ 144`; deletion closures take Tan's bounds and the `(10,23)` certificate bound as explicit hypotheses ("they cannot honestly be erased from a certificate-free theorem statement"); axioms only `propext`, `Classical.choice`, `Quot.sound`; no `sorry`/`native_decide` (grep-verified) [dfield26 §5]. **What Lean never touches there:** SAT/MIP certificates, CNF/OPB encoding correctness including symmetry breaking and the min-row cut, cube-cover and orbit-cover completeness, the 25-profile enumeration, and the 1,577-configuration residue enumeration — all Python or external checkers [dfield26 §5.5]. Nobody outside the LLM-driven session has replayed the certificates or built the Lean project.

Relative to dfield, the thesis proposes to add, in decreasing order of certainty:

1. **A gate that is problem-generic and evolution-facing.** dfield's Lean is a per-cell formalisation written once by LLM agents; ZarPrune's `Prune P` is a fixed obligation that any candidate for any `(m,n,s,t,w)` must meet, with a negative test (`notDescending_unsound`) that formalises the pruning-vs-adding distinction dfield handles by convention. All of dfield's prunes are histogram functions and transfer unchanged as `kill` predicates on our finer `Profile` [dfield26 §9].
2. **Both sums fixed, with Tan's cross prunes.** dfield fixes only column histograms (coarse branches, heavy leaves, complete row breaking); Tan/ZarPrune fix both (stronger counting prunes such as Argument D, partially broken symmetry). This is a measurable trade-off the thesis can quantify [symmetry_breaking_matrices §7.1, §11.1].
3. **Certificates checked in Lean, and an encoding-correctness theorem.** Discharging `refuted` through Lean core's verified LRAT checker with a completeness theorem for the branch encoding would be the first Zarankiewicz result whose SAT half is Lean-checked; dfield checks LRAT externally and proves nothing about its encoding [dfield26 §5.5] [lean_verified_sat_and_sandbox §9].
4. **A cover obligation stated and discharged in Lean** (decidable enumeration over bounded profiles, or `cover_unsat` for solver cubes), where dfield's `classify_*` theorems cover ≤ 5 profiles and its cube/orbit covers are Python-checked.
5. **Difficulty-weighted, ungameable rewards** built from candidate-independent probes (§5), where dfield's only in-loop estimator is a 20k-conflict budget and its only post-hoc measure is proof size; and a difficulty model calibrated on Tan's 1,650 recomputable cases, which none of the sources have timed.
6. **The search itself**: an evolutionary loop that proposes counting arguments (Farkas combinations, residue arguments with evolved moduli and marked sets, cross-side inequalities) and gets each one kernel-checked — the "candidate and its Lean proof, automatically" that Tao–Wagner name as open.
7. **A provenance-tagged bound ledger** (proved here / imported from Tan / from an unreviewed preprint) threaded into conditional prunes, plus a mechanical claim checker (monotonicity, `z(m,n+1) ≤ z(m,n)+m`, witness comparison) that refutes three of Padhi's cells by itself [padhi2026_gpu L3].

What the thesis should *not* claim to add: new closed-form counting theory (the classical inequalities are all one double count plus convexity), a complete symmetry break for row–column symmetry (impossible unless GI ∈ coNP), or a Lean-free replacement for certificates.

## 10. Gaps and opportunities

**Gaps in the literature.**

* No wall-clock or per-case difficulty data exists for any Zarankiewicz case split: Tan reports none, dfield stripped theirs, Hou and Afrasyab use no solver. A calibrated difficulty model is therefore new work; the 1,650 Kyoto cases plus the project's training-ladder tables (E3) are the natural data set [tan_kyoto_repo §14] [sat_hardness_estimation §9].
* No source defines "difficulty of a partition pair"; the best cheap ranker found (one-decision-deep propagation rate, `ρ = −0.65`) is a 14-sample pilot; whether it holds across cells, and what conflict cap orders survivors on a target cell, are open [sat_hardness_estimation §5, §9].
* Nobody has proved in Lean that a Zarankiewicz CNF encoding (with cardinality constraints and lex symmetry breaking) is complete for the matrix semantics; the closest precedents are Keller (Trestle, Mathlib) and Lean core's Tseitin. Nor has anyone certified a cube-cover or partition-enumeration completeness in Lean beyond ≤ 5 profiles [dfield26 §11] [lean_verified_sat_and_sandbox §11].
* No published loop combines a construction/argument evaluator with an in-loop Lean checker; the two nearest (DeepMind proof-sketch evolution, ProofEvolve) evolve proofs of fixed statements. The pass rate of frontier models on ZarPrune-style lemmas is unmeasured and needs a 10–20 problem pilot [alphaevolve_and_math_discovery §9] [llm_lean_provers_2026 §7].
* The 2026 frontier results rest on unreviewed, AI-assisted artefacts: dfield (0 stars, 25 GB unreplayed), Afrasyab (retracted two earlier claims; nobody has replayed the package), Hou (uniqueness import). A partial Lean replay of any of these would itself be a contribution the authors request [afrasyab2026_slices §11.7] [dfield26 §11.1].
* Guy's original argument letters, the Handbook cube-and-conquer chapter, Knuth 1975, Roman 1975, Čulík, Reiman, Goddard–Henning–Oellermann, Grayland snake-lex, the OOPSLA bv_decide paper and the IJCAR 2026 SMS+Lean paper were not accessible; everything attributed to them is second-hand.

**Opportunities the sources point to, roughly in the order the thesis should take them.**

1. **Milestone 0, no SAT:** with P1 + P2 + P4/P5 + P8 as verified prunes and a decidable `cover`, reproduce every DGH `(3,3)` improvement and the 30 IP cells with empty survivor lists — a fully verified deliverable that exercises the cover seam [dgh2024_lp_bounds §12].
2. **Close the `refuted` seam in Lean** on the training ladder (`(9,9,50)`: 36 certificates, 3.8 MB) using `LRAT.check_sound`, an `Encode.lean` completeness theorem for the sequential-counter encoding, and `exists_doubleLex` for the lex clauses; cross-check tiny instances against `bv_decide` [lean_verified_sat_and_sandbox §9].
3. **Make neighbour bounds first-class**: `CondPrune P tbl` with a provenance ledger, so a closed cell automatically strengthens P4/P5 at `(m+1,n)` and `(m,n+1)`; this is the mechanism Tan, Collins, dfield and Afrasyab all rely on and the answer to the proposal's "does our work generalise to other cases" question [hou2026_13x18 §8] [saurabh2026_five_lb §10].
4. **Point the search at the untapped room**: cross-side inequalities (D-type arguments coupled with the other side's profile), `(3,3)` residue/overlap arguments with evolved marked sets and moduli (P14–P16, whose case proofs are "library identities + `decide` constants + `omega`"), and Farkas combinations with an exact LP oracle; reward marginal kills over the strong baseline weighted by §5's hardness, with the tail statistic reported [dfield26 §9] [zarankiewicz_theory_counting §7] [sat_hardness_estimation §8].
5. **Enrich the case index** beyond `(r, c)` — max pair-codegree `β`, number of columns of each size, or the first rows' supports — to turn `D_v` cuts, Füredi-type and DHS Prop 3.20 arguments into provable prunes; this is the bridge to AlphaMapleSAT-style sub-cubing (a partition branch *is* a cube over counter literals once unary counters are in the base CNF) and to Chivilikhin's "triples of backdoors beat pairs" [zarankiewicz_theory_counting P11] [alphamaplesat §8.1] [chivilikhin2023_decomp §6.5].
6. **A second, weaker gate for additions**: candidates that fail `Prune.sound` because they are orbit-dominance claims (`Dominated : ∀ A, kill (profileOf A) → Valid P A → ∃ σ τ, ¬kill (profileOf (act σ τ A))`) could be re-targeted as SR/dominance witness generators rather than discarded; adjacent-swap-within-block SR witnesses are mechanical and no solver emits them yet [symmetry_breaking_matrices §11.4, §11.6].
7. **Targets**: calibrate on `(10,20)`, `(11,21)`, `(11,22)`, `(12,22)` and `(12,18,109)`; then `(16,18) ≤ 139`, `(16,17) ≤ 132`, the `m = 13` cells with gaps 4–9, and `z(17;3) ≤ 140` (49 near-regular pairs); run the lower-bound machinery in parallel as a soundness canary, since Afrasyab's unsound certificates were caught only by witnesses [afrasyab2026_slices §9.8].
8. **Report what the predecessors did not**: per-phase cost, invalid/crash rates, ablations of islands/G2/multipliers (none exist for the lower-bound paper), multi-run statistics (FunSearch: 4/140; BaSE: single runs unreliable), and an axiom ledger per bound [bhan2026_lower_bounds §13] [alphaevolve_and_math_discovery §8.4].
